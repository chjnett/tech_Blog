Q, K, V는 대체 뭘까 — scaling은 왜 하는가

attention 코드를 처음 봤을 때 제일 헷갈렸던 게 Q, K, V였다. 셋 다 그냥 입력을 선형변환한 것뿐인데 왜 이름이 다르고, 왜 셋으로 쪼개는지 감이 안 왔다. 직접 구현해보면서 이해한 걸 정리해본다.

Q, K, V는 각자 다른 질문에 답한다

Query는 "지금 이 위치가 뭘 찾고 있는가", Key는 "각 위치가 뭘 갖고 있다고 광고하는가", Value는 "실제로 넘겨줄 정보가 뭔가"다. Query와 Key를 비교해서 얼마나 관련 있는지 점수를 매기고, 그 점수만큼 Value를 섞어서 가져온다.

Q, K, V의 역할 — Query가 Key와 얼마나 비슷한지 비교해서, Value를 얼마나 가져올지 정한다

처음엔 "그냥 입력 하나면 되지 왜 셋으로 나누냐"고 생각했는데, 역할을 분리해야 모델이 "뭘 찾을지"와 "뭘 줄지"를 따로 학습할 수 있다는 걸 나중에 이해했다. 셋 다 같은 입력에서 나오지만, 서로 다른 가중치 행렬을 거치니까 완전히 다른 표현이 된다.

왜 √d_k로 나누는가

Q·K 내적값은 차원(d_k)이 커질수록 값 자체가 커진다. 값이 크면 softmax가 한쪽으로 확 쏠려버려서(거의 0 아니면 1) 그래디언트가 죽는다. 그래서 √d_k로 나눠서 값의 스케일을 일정하게 유지한다 — 이게 "scaled" dot-product attention에서 scaled의 의미였다.

python 
# Q, K, V를 받아 attention 가중치를 계산한다
def scaled_dot_product_attention(q, k, v):
    d_k = q.size(-1)
    scores = q @ k.transpose(-2, -1) / (d_k ** 0.5)
    weights = scores.softmax(dim=-1)
    return weights @ v

실제로 scaling을 빼고 돌려보니 loss가 초반부터 거의 안 줄어드는 걸 확인했다.

scaling 유무 비교 — python train.py 
$ python train.py --scaling true
epoch 1 | loss 4.83
epoch 5 | loss 2.91
epoch 10 | loss 1.72

$ python train.py --scaling false
epoch 1 | loss 4.79
epoch 5 | loss 4.61
epoch 10 | loss 4.55  # 거의 안 줄어듦
